## 기본 모델: F1 Ratio + F1 Hard Sampler + Mass2

### Canonical config

```text
configs/experiment/pinn/model_260803_f1_ratio_hard_mass2.yaml
```

이 문서는 2026-08-03 기준 기본 모델의 구조, 학습 방식, sampler와 설계 이유를

## 3. Node 입력

### 3.1 Operating feature dimension

```text
Original operating slots                         13D
Raw known feeds: CH4, AIR, WATER                  3D
log(AIR/CH4), log(WATER/CH4)                      2D
-----------------------------------------------------
x_oper                                            18D
x_oper_mask                                       18D
```

현재 mask 처리 방식은 `concat`이다.

```text
x_oper 18 + x_oper_mask 18
= 36D
  -> operating encoder: 36 -> 64
```

최종 node 초기 입력은 다음과 같다.

```text
Node role embedding                               32D
Unit type embedding                               24D
Operating embedding                               64D
-----------------------------------------------------
Node encoder input                               120D
  -> input MLP: 120 -> 384 -> 384
= initial node hidden h0                         384D
```

HX role embedding은 사용하지 않는다.

### 3.2 Feed와 ratio가 들어가는 node

| Node | CH4/AIR/WATER | Log ratios |
|---|---:|---:|
| `V_INPUT` | 적용 | 적용 |
| `BURNER`, `R3_BURNER` | 미적용 | 적용 |
| 나머지 node | 미적용 | 미적용 |

모든 node의 tensor 폭은 18D로 동일하다. 사용하지 않는 slot은 다음과 같다.

```text
value = 0
mask  = 0
```

Ratio 기능은 P03 전용이 아니다. 활성화된 run에서는 P01-P10 모든 공정의
`V_INPUT`에 적용하고, BURNER semantic token을 가진 node가 있으면 그 node에도
적용한다.

### 3.3 Ratio 수식과 validity mask

```text
epsilon = 1e-6

r_air   = log((AIR   + epsilon) / (CH4 + epsilon))
r_water = log((WATER + epsilon) / (CH4 + epsilon))
```

다음 조건에서는 ratio를 사용하지 않는다.

```text
CH4 missing
CH4 <= epsilon
AIR 또는 WATER missing
입력값이 finite하지 않음
```

이때 ratio는 `value=0`, `mask=0`이다. 분모에 epsilon만 넣어 비정상적으로 큰
ratio를 만드는 대신, 입력이 유효하지 않다는 사실을 명시적으로 전달한다.

### 3.4 Ratio를 넣는 이유

Raw feed만 사용하면 모델이 나눗셈 관계와 연소 regime을 MLP와 GNN 안에서 직접
학습해야 한다. 제한된 epoch sampling에서는 이 관계를 안정적으로 발견하기 어렵다.

명시적인 ratio는 다음 inductive bias를 제공한다.

- 절대 유량이 달라도 유사한 연소 regime을 인식한다.
- P03 CO 변화와 직접 연관된 좌표계를 제공한다.
- V_INPUT은 graph 전체 feed context를 제공한다.
- BURNER는 local combustion context를 제공한다.
- process ID나 CO 정답을 입력으로 사용하지 않는다.

Ratio는 raw feed의 deterministic transform이다. 새로운 관측값을 만드는 것이 아니라
모델이 학습하기 쉬운 물리적 좌표계로 입력을 재표현한다.

## 5. Bidirectional FlowGNN

### 5.1 방향별 attention

5개 layer 각각에서 두 방향을 별도로 계산한다.

```text
Forward:  upstream source -> downstream destination
Backward: downstream destination -> upstream source
```

각 방향은 node hidden과 edge embedding으로 scalar attention을 계산한다.

```text
Forward hidden                                    384D
Backward hidden                                   384D
  -> concat                                       768D
  -> directional fusion                           384D
```

Forward는 원료와 상류 운전조건 전달에 적합하고, backward는 출구 위치와 하류 장치
문맥을 upstream representation에 전달한다. 두 방향을 분리한 뒤 fusion하여 유동
방향의 의미를 보존한다.

### 5.2 Layer residual

```text
h_interp = h_prev + 0.5 * (h_new - h_prev)
         = 0.5 * h_prev + 0.5 * h_new
```

이 interpolation은 한 layer의 출력이 기존 표현을 한 번에 덮어쓰는 것을 막고,
deep GNN의 over-smoothing과 학습 불안정을 줄인다.

### 5.3 Initial-state injection

각 layer에서 초기 node hidden을 다시 넣는다.

```text
h <- h_interp + 0.05 * h0
```

Operating condition과 feed ratio가 깊은 message passing에서 topology 정보에 묻히지
않게 하는 장치다. 작은 0.05 계수로 초기정보를 보존하되 새 graph representation의
형성을 방해하지 않도록 한다.

최종 local node hidden은 384D다.

## 7. Edge descriptor

각 edge `e=(i,j)`의 descriptor는 다음과 같다.

```text
Source local node h_i                           384D
Destination local node h_j                      384D
Projected global context                        384D
GNN edge embedding                              384D
----------------------------------------------------
Edge descriptor z_e                            1536D
```

Source와 destination을 순서 있게 연결하므로 edge 방향이 보존된다. Property Role16
direct concat과 Target Branch Hidden Adapter는 이 기본 모델에서 비활성이다.

## 8. Hierarchical Reduced PI Head

### 8.1 Shared decoder

```text
1536
  -> Linear 768
  -> LayerNorm
  -> GELU
  -> Dropout 0.1
  -> Linear 384
  -> LayerNorm
  -> GELU
  -> Dropout 0.1
= shared edge latent 384D
```

중간 폭 768과 출력 폭 384가 다르므로 shared decoder residual은 비활성이다.

### 8.2 Level-1 branches

```text
Condition: 384 -> 96 -> 2
  -> Temp, Pres

Fraction: 384 -> 128 -> 7
  -> H2O, H2, CH4, CO2, CO, O2, N2

Mass: 384 -> 96 -> 1
  -> Mass_Flow
```

공유 latent는 공통 stream 상태를 보존하고, 분리된 branch는 서로 다른 물성 scale과
gradient conflict를 줄인다.

### 8.3 Fraction softmax

```text
x_hat_k = exp(a_k / 0.5) / sum_j exp(a_j / 0.5)
```

따라서 `x_hat_k >= 0`, `sum_k x_hat_k = 1`이 구조적으로 보장된다. 중복되는 CLR
loss와 closure penalty는 사용하지 않는다.

### 8.4 Detached Vol_Flow branch

```text
Temp 1 + Pres 1 + Fractions 7 + Mass_Flow 1
= Level-1 prediction 10D

detach(Level-1 10D)
  -> 10 -> 32 -> 1
  -> Vol_Flow
```

Volume loss gradient가 Temp, Pres, fraction, Mass branches를 흔드는 것을 막는다.
Volume은 Level-1 예측을 사용하지만 Level-1 parameter에는 역전파하지 않는다.

### 8.5 최종 출력

```text
Temp + Pres                                        2
Fractions                                          7
Mass_Flow                                          1
Vol_Flow                                           1
-----------------------------------------------------
Final stream output                               11D
```

`Mole_Flow`, `Density`, `Enthalpy`는 직접 예측하지 않는다.

## 9. Edge supervision

```text
Main loss: Smooth L1
Default edge weight: 1
Target edge weight: 5
Fraction log-loss weight: 0.75
Mass_Flow log-loss weight: 2.0
```

Mass_Flow weight 2.0은 원래 F1의 1.0 대비 정확히 2배다. Mass_Flow의 넓은 동적
범위 때문에 scaled-log 공간에서 학습하며, 별도의 physical-space Mass auxiliary
loss는 비활성이다.

True flow가 사실상 0인 edge는 fraction loss와 fraction metric에서 제외한다.
Target weight를 과거 40이 아니라 5로 둬 target은 강조하되 all-edge 표현 붕괴는
방지한다.

## 10. Sample-hybrid optimizer update

`batch_size=1`이며 sample 하나에서 다음 순서로 업데이트한다.

```text
1. Non-target edge groups
   -> fresh forward
   -> group macro mean
   -> backward and optimizer step once

2. Each target edge group
   -> fresh forward per target
   -> independent loss
   -> backward and optimizer step once per target

3. Node PINN + supervised anchor
   -> fresh forward
   -> joint loss
   -> backward and optimizer step once
```

Target edge가 3개라면:

```text
non-target 1 + target 3 + node 1
= 5 forwards and 5 optimizer updates
```

Target별 독립 update는 어려운 CO와 CH4 gradient가 많은 non-target edge 평균에
묻히는 것을 막는다.

## 11. Node PINN

활성 항목은 Mass, Component, Atom balance다. Energy PINN, Density, Enthalpy 및
별도 Volume PINN loss는 비활성이다.

### 11.1 공통 relative residual

Edge quantity `q_e`에 대해:

```text
R_v(q) = sum_(e in In(v)) q_hat_e
       - sum_(e in Out(v)) q_hat_e

S_v(q) = sum_in |q_true_e| + sum_out |q_true_e|

r_v(q) = R_v(q) / (max(S_v(q), 1.0) + 1e-6)
```

Residual은 `[-10, 10]`으로 clip하고 delta 0.5 Huber loss를 적용한다.

### 11.2 Mass balance

```text
R_mass(v) = sum_in m_hat_e - sum_out m_hat_e
```

Internal node에 적용하며 weight는 0.75다.

### 11.3 Component molar balance

```text
MW_mix,e = sum_k x_hat_(e,k) * MW_k
n_total,e = m_hat_e / max(MW_mix,e, epsilon)
n_hat_(e,k) = n_total,e * x_hat_(e,k)

R_component(v,k)
  = sum_in n_hat_(e,k) - sum_out n_hat_(e,k)
```

Non-reactive internal node에 적용하며 weight는 `1.5e-7`이다. 작은 weight는 component
residual의 큰 원래 수치 scale을 보정하기 위한 것이다.

### 11.4 Atom balance

Species-atom matrix `A_(k,a)`를 사용한다.

```text
F_hat_(e,a) = sum_k n_hat_(e,k) * A_(k,a)

R_atom(v,a)
  = sum_in F_hat_(e,a) - sum_out F_hat_(e,a)
```

Reactive internal node에 적용하며 weight는 0.2다. 반응기에서는 성분별 유량은
바뀔 수 있지만 원자수는 보존되어야 하므로 component와 적용 node를 분리한다.

### 11.5 Supervised anchor

```text
L_node
  = 0.75   * L_mass
  + 1.5e-7 * L_component
  + 0.2    * L_atom

L_node_update
  = 1.0 * L_supervised_anchor
  + 0.05 * s(epoch) * L_node
```

PINN만 단독으로 업데이트하지 않고 supervised anchor를 함께 사용해 physics gradient가
data-fit representation을 붕괴시키는 것을 방지한다. Anchor에는 target weight 5를
다시 적용하지 않는다.

### 11.6 PINN schedule

| Epoch | `s(epoch)` | 의미 |
|---|---:|---|
| 1-5 | 0.0 | supervised representation 우선 형성 |
| 6-7 | 0.5 | node PINN 절반 강도 도입 |
| 8 이후 | 1.0 | node PINN 전체 강도 적용 |

Schedule은 node PINN에만 적용된다. Edge supervised loss는 epoch 1부터 계속 활성이다.

## 12. Original F1 hard sampler

전체 train pool에서 매 epoch 2,000개의 unique graph sample을 선택한다.

| 구성 | 개수 | 목적 |
|---|---:|---|
| Base sampler | 1,000 | 전체 공정과 일반 분포 유지 |
| Target Frac_CO hard | 400 | 어려운 CO target 보강 |
| Target Mass_Flow high | 240 | 100k 이상 500k 미만 보강 |
| Target Mass_Flow extreme | 160 | 500k 이상 보강 |
| Target Frac_CH4 hard | 200 | sparse CH4 target 보강 |
| **합계** | **2,000** | |

새 기본 YAML의 `epoch_sampler` 전체 dictionary는 원래 F1 YAML과 동일하다.

### 12.1 Base 1,000

| Bucket | 설정 비율 |
|---|---:|
| Uniform | 25.0% |
| Sparse-positive fraction | 37.5% |
| Property quantile balance | 25.0% |
| Mass_Flow tail mixture slot | 12.5% |

별도 `mass_flow_tail.enabled`는 false다. 실제 고유량 확보는 hard Mass 400개가
담당한다. Process balance와 epoch 내 unique sampling을 유지한다.

### 12.2 Hard 1,000

```text
Frac_CO 400:
P03_E014 중심 + P05/P06/P07/P10 support edges

Mass_Flow 400:
high 240 + extreme 160

Frac_CH4 200:
P06/P07/P08 target edges
```

P03 CO hard selection은 true Frac_CO threshold를 사용한다. 따라서 이 sampler는
label-free가 아니다. 기존 F1 sampler의 성능상 이점을 유지하는 대신 label-based
sampling 편향을 받아들인 구성이다.

AIR/CH4 transition sampler를 사용하려면 별도 C2/C3 ablation 설정을 사용해야 한다.

