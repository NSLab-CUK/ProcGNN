> Historical 11D document. Current canonical documentation:

## 1. 최종 모델 선언

`MODEL 260805`는 다음 실험 구성을 최종 기본 모델로 고정한 버전이다.

```text
R1-HX-F64
= Relational Bidirectional FlowGNN
+ HX inlet/outlet pair relation
+ FeedHead 64D
+ Hierarchical Reduced PI Head
```

- 최종 설정 파일: `configs/experiment/pinn/model_260805.yaml`
- 기본 실험명: `model_260805`
- 기본 출력 폴더: `outputs/model_260805`
- 예측 대상: 11개 stream property
- 전체 파라미터: **22,753,190개**
- 최종 edge head 관련 파라미터: **2,252,220개**
- 기본 데이터 분할: 전체 공정 60/20/20 outer 5-fold의 fold 1

기존 `R1-HX-F64` 설정에서 실험명과 저장 경로만 바꾸었다. 모델 구조, sampler,
loss, optimizer, PINN 설정은 성능을 확인한 R1-HX-F64와 동일하다.

## 2. 이 모델을 최종 선택한 이유

동일한 validation 조건에서 R 계열을 비교했을 때 R1-HX-F64가 성능과 계산량의
균형이 가장 좋았다.

| 모델 | Target 성분 평균 R2 | All-edge 성분 평균 R2 | 해석 |
|---|---:|---:|---|
| R1 | 0.95406 | 0.96501 | relational GNN 기준 모델 |
| R2-A | 0.92722 | 0.95934 | 양방향 edge readout이 이 실험에서는 불리 |
| R2-B | 0.95318 | 0.96214 | decoder를 키워도 R1-HX-F64보다 낮음 |
| R3 | 0.95388 | 0.95871 | 방향 표현을 합치는 과정에서 정보 손실 가능 |
| **R1-HX-F64** | **0.96093** | **0.96627** | **최종 선택** |

R1-HX-F64의 주요 성능은 Target CH4 0.96617, Target CO 0.95857,
Target CO2 0.99557, Target Mass Flow 0.97216, All-edge CO 0.98505,
All-edge Mass Flow 0.97776이었다.

최종 선택의 핵심 이유는 다음과 같다.

1. **R1 relational GNN**이 stream edge 정보를 message와 attention 양쪽에 사용한다.
2. **HX pair relation**이 열교환기 내부의 inlet/outlet 유로 대응 정보를 보충한다.
3. **FeedHead64**가 원료 공급 조건을 head에 직접 전달하여 GNN 깊이 안에서 정보가
   희석되는 것을 줄인다.
4. R2/R3처럼 최종 edge readout까지 복잡하게 바꾸지 않아 계산량과 최적화 난도가
   상대적으로 낮다.
5. Target weight 5, log-space Mass Flow weight 2, 단계적 PINN schedule을 사용하여
   과도한 gradient를 피한다.

## 4. Node 입력과 초기 embedding

### 4.1 Operating feature

모든 node는 같은 폭의 18D operating tensor를 갖는다.

| 구성 | 차원 | 적용 방식 |
|---|---:|---|
| 기존 operating variables | 13 | 원래 공정 조작 변수 |
| CH4, AIR, WATER feed | 3 | V_INPUT node에 주입 |
| log(AIR/CH4), log(WATER/CH4) | 2 | V_INPUT과 BURNER node에 주입 |
| 합계 | **18** | 값이 없는 위치는 mask=0 |

비율 feature는 다음과 같이 계산한다.

```text
r_air   = log((AIR   + 1e-6) / (CH4 + 1e-6))
r_water = log((WATER + 1e-6) / (CH4 + 1e-6))
```

CH4가 없거나 0에 가까운 경우 mask로 무효 처리한다. 모든 node의 tensor 폭은 18D로
같지만, 실제 값이 주입되지 않은 node는 해당 slot의 mask가 0이다.

`oper_mask_mode=concat`이므로 값 18D와 mask 18D를 붙인다.

```text
[operating value 18; operating mask 18] = 36D
36 -> Linear -> ReLU -> LayerNorm = 64D
```

### 4.2 Node 초기 hidden

```text
Node role embedding                  32D
Unit type embedding                  24D
Encoded operating feature            64D
                                      ---
Node encoder input                   120D
120 -> 384 -> 384
= initial node hidden h0             384D
```

node input MLP는 2층이며 dropout 0.1을 사용한다. HX role embedding은 이 최종
모델에서 사용하지 않는다. HX 정보는 일반 node category가 아니라 명시적인 edge pair
relation으로 처리한다.

## 5. Stream edge 입력

```text
Generic stream role embedding        24D
Canonical stream ID embedding        32D
Structural attributes                 3D
  -> Linear 3 -> 16, ReLU, LayerNorm 16D
                                      ---
Edge encoder input                    72D
72 -> 384 -> 384
= static edge embedding e            384D
```

Stream ID를 유지하는 이유는 동일한 source/destination를 공유하는 평행 stream을
구분하기 위해서다. 이 ID는 vocabulary 512 안에서 32D로 embedding된다.

edge embedding은 5개 GNN layer에서 message와 attention을 조건화하지만, layer마다
갱신되지는 않는다. 즉 `update_edge_embeddings=false`인 **static relation feature**다.

## 6. 5-layer Relational Bidirectional FlowGNN

### 6.1 이 FlowGNN이 일반적인 node-only GNN과 다른 점

이 모델은 node 연결만 보는 GNN이 아니다. 원래 방향이 `i -> j`인 모든 stream edge에
대해 현재 node hidden과 **해당 stream의 고정 edge embedding**을 함께 사용한다.

```text
Layer l input
  node hidden h^(l-1): [N_node, 384]
  static stream e:     [N_edge, 384]
  edge_index:          [2, N_edge]

Forward branch:  physical flow i -> j
Backward branch: reverse information j -> i
```

다섯 layer는 서로 다른 parameter를 가진다. 그러나 edge embedding `e_ij` 자체는
한 번만 만들고 갱신하지 않으며, **동일한 `e_ij`를 다섯 layer의 message와 attention에
매번 다시 넣는다.** 따라서 node 정보와 edge 정보의 반복 주입은 서로 다른 두 경로다.

- node 초기 정보: 최초 hidden `h0`를 layer마다 residual로 다시 더한다.
- edge 초기 정보: 최초 static edge embedding `e_ij`를 layer마다 message/attention
  입력으로 다시 사용한다.

이 구조를 택한 이유는 공정 topology가 같아도 stream의 종류와 위치가 다르면 전달해야
할 정보가 달라지기 때문이다. edge를 매 layer 갱신하지 않는 것은 stream identity를
안정적으로 보존하고 계산량과 최적화 불안정을 줄이기 위한 선택이다.

### 6.2 순방향 message: 유입 stream을 destination에서 경쟁

물리적 흐름이 `i -> j`인 edge의 layer `l` 순방향 message는 다음과 같다.

```text
m_ij_f = M_f([h_i^(l-1); e_ij])

[h_i 384; e_ij 384] = 768
M_f: 768 -> 512 -> 384
```

message 크기뿐 아니라 어떤 유입 stream을 중요하게 볼지도 edge-conditioned attention으로
계산한다.

```text
s_ij_f = A_f([h_i^(l-1); h_j^(l-1); e_ij])

[h_i 384; h_j 384; e_ij 384] = 1152
A_f: 1152 -> 256 -> 1
```

destination `j`로 들어오는 edge 집합 `In(j)` 안에서만 softmax를 적용한다.

```text
alpha_ij_f = exp(s_ij_f) / sum_(k->j in In(j)) exp(s_kj_f)

a_j_f = sum_(i->j in In(j)) alpha_ij_f * m_ij_f
```

즉 mixer, reactor, separator처럼 여러 stream이 한 장치로 들어올 때, 서로 무관한 graph
전체 edge가 아니라 **그 destination으로 실제 유입되는 stream끼리만 경쟁**한다.

### 6.3 역방향 message: 하류 정보를 physical source로 전달

같은 물리 edge `i -> j`에 대해 역방향 branch는 destination `j`의 정보를 source `i`로
보낸다.

```text
m_ij_b = M_b([h_j^(l-1); e_ij])

[h_j 384; e_ij 384] = 768
M_b: 768 -> 512 -> 384

s_ij_b = A_b([h_j^(l-1); h_i^(l-1); e_ij])

[h_j 384; h_i 384; e_ij 384] = 1152
A_b: 1152 -> 256 -> 1
```

역방향 attention은 physical source `i`에서 나가는 edge 집합 `Out(i)` 안에서 정규화한다.

```text
alpha_ij_b = exp(s_ij_b) / sum_(i->k in Out(i)) exp(s_ik_b)

a_i_b = sum_(i->j in Out(i)) alpha_ij_b * m_ij_b
```

순방향은 `destination` 기준, 역방향은 `source` 기준이라는 차이가 중요하다. 순방향은
장치로 섞여 들어오는 유입의 중요도를 나타내고, 역방향은 한 장치에서 갈라져 나가는
하류 경로 중 어떤 경로가 상류 상태 해석에 중요한지를 나타낸다. 두 branch의 message,
attention, update parameter는 공유하지 않는다.

### 6.4 Attention과 aggregation의 수치적 동작

attention head는 방향당 하나의 scalar head다. attention MLP는
`Linear -> GELU -> Linear`이며, message/update/fusion MLP는
`Linear -> LayerNorm -> GELU -> Dropout(0.1) -> Linear`이다.

softmax는 group별 최대 logit을 먼저 빼는 안정화 계산을 사용하고 분모에는 최소
`1e-12`를 둔다. 유입 또는 유출 edge가 없는 node의 aggregate는 384D zero vector가
된다. 그런 node도 이후 update에서 현재 node hidden을 함께 받으므로 정보가 갑자기
사라지지 않는다.

batch에 graph가 여러 개 있더라도 collate된 node index가 graph별로 분리되어 있어
attention 경쟁과 scatter sum이 graph 경계를 넘지 않는다. 현재 최종 학습은 batch size
1이지만 연산 자체는 multi-graph batch를 지원한다.

### 6.5 방향별 update와 fusion

aggregate만 node hidden으로 쓰지 않고 현재 node 상태를 다시 결합한다.

```text
u_i_f = U_f([h_i^(l-1); a_i_f])
u_i_b = U_b([h_i^(l-1); a_i_b])

[current node 384; directional aggregate 384]
  -> 768 -> 512 -> 384

h_tilde_i^l = F([u_i_f; u_i_b])

[forward update 384; backward update 384]
  -> 768 -> 512 -> 384
```

여기에는 두 단계의 정보 보존이 있다.

1. 각 directional update가 현재 `h_i^(l-1)`을 직접 입력으로 받는다.
2. 그 뒤 outer layer residual이 이전 hidden을 다시 보존한다.

따라서 message가 작거나 특정 방향의 edge가 없는 node도 자기 상태를 유지할 수 있다.
5개 layer를 쌓으면 한 layer당 양방향으로 한 hop씩 전달되므로, 최종 local hidden은 최대
5-hop 범위의 상류와 하류 문맥을 함께 담는다.

### 6.6 Layer residual connection

fusion 출력 `h_tilde^l`을 그대로 다음 layer로 보내지 않고 이전 hidden과 선형 보간한다.

```text
h_interp^l
  = h^(l-1) + 0.5 * (h_tilde^l - h^(l-1))
  = 0.5 * h^(l-1) + 0.5 * h_tilde^l
```

이 residual의 목적은 다음과 같다.

- 한 layer의 attention이 일시적으로 잘못 집중해도 표현 전체가 즉시 바뀌지 않는다.
- 5-layer 역전파에서 이전 hidden으로 가는 직접 gradient 경로를 남긴다.
- 고정 topology에서 node 표현이 비슷해지는 over-smoothing 속도를 낮춘다.
- target edge별 fresh optimizer step에서 발생할 수 있는 표현의 급격한 이동을 완화한다.

`layer_residual_norm=false`이므로 이 보간 뒤에는 별도 LayerNorm을 적용하지 않는다.
LayerNorm은 message/update/fusion MLP 내부에만 있다.

### 6.7 최초 node 정보 `h0`의 per-layer 재주입

layer residual 다음에 node input encoder가 만든 최초 hidden `h0`를 다시 더한다.

```text
h^l = h_interp^l + 0.05 * h0
```

`h0`에는 node role, unit type, operating value/mask, V_INPUT feed, 그리고 활성 node의
log feed-ratio 정보가 들어 있다. 이 신호를 5개 layer 모두에 재주입하는 이유는 깊은
message passing 중에도 **원래 그 node에 주어진 관측값과 역할을 잊지 않게 하기 위해서**다.

정확한 전체 recurrence는 다음과 같다.

```text
h^0 = NodeInputEncoder(raw node information)

for l = 1..5:
    h_tilde^l = FlowGNNLayer_l(h^(l-1), edge_index, static e)
    h^l = 0.5*h^(l-1) + 0.5*h_tilde^l + 0.05*h^0
```

`0.05*h0`는 다섯 번 단순 합산되어 마지막에 `0.25*h0`가 되는 구조가 아니다. 이전
layer에서 더해진 `h0`도 다음 layer의 message, attention, update를 다시 통과하므로 각
경로의 효과는 학습된 비선형 변환을 거친다.

또한 세 계수의 합이 1.05이므로 엄밀한 convex combination은 아니다. `0.05`는 약한
input anchor이고, MLP 내부 LayerNorm과 작은 residual 계수로 scale을 제어한다.
`initial_residual_mode=per_layer`이므로 5번째 layer 뒤에 `h0`를 별도로 한 번 더 더하지
않는다. YAML의 `input_residual=true`는 이전 config 호환용 표기이고 실제 동작을 결정하는
값은 `initial_residual_mode=per_layer`와 `initial_residual_alpha=0.05`다.

### 6.8 Static edge 정보의 per-layer 재사용

edge embedding은 다음처럼 최초 한 번만 계산한다.

```text
e_ij = EdgeInputEncoder(stream role, stream ID, structural attributes)
```

그 뒤 모든 layer가 같은 `e_ij`를 받는다.

```text
Layer 1: FlowGNNLayer_1(h0, edge_index, e)
Layer 2: FlowGNNLayer_2(h1, edge_index, e)
...
Layer 5: FlowGNNLayer_5(h4, edge_index, e)
```

즉 `update_edge_embeddings=false`는 edge 정보를 첫 layer에서만 쓴다는 뜻이 아니다.
**갱신하지 않은 원래 edge 정보를 매 layer에 반복 조건으로 제공한다는 뜻**이다. 평행
edge와 서로 다른 stream role이 node mixing 과정에서 지워지지 않는 장점이 있고, 매
layer edge state를 새로 만드는 비용과 불안정성도 피한다.

### 6.9 Gradient 관점에서 본 두 residual 경로

한 layer에는 이전 hidden으로 가는 직접 계수 `0.5`의 gradient 경로가 있고, 모든
layer 출력에는 `h0`로 가는 직접 계수 `0.05`의 경로가 추가된다. 따라서 loss gradient는
다음 두 종류로 input encoder에 도달한다.

```text
loss -> nonlinear message/attention path -> h0
loss -> layer residual / repeated initial anchor -> h0
```

이것이 residual connection과 initial reinjection을 함께 쓰는 핵심 이유다. residual은
**직전 layer 상태**를 보존하고, initial reinjection은 여러 layer 전파 후에도
**원래 입력 의미**를 보존한다. 둘은 같은 기능의 중복이 아니다.

### 6.10 FlowGNN 뒤에서 추가되는 정보와의 경계

- HX pair relation은 FlowGNN 내부에 넣지 않고 최종 edge embedding에만 적용한다.
- FeedHead64도 message passing 내부가 아니라 property head 직전에 붙인다.
- 따라서 FlowGNN은 보편적인 방향성 stream 전달을 학습하고, HX pairing과 direct feed는
  필요한 위치에서만 보정한다.

이 분리는 세 방법이 서로의 역할을 침범하지 않게 한다. FlowGNN은 local propagation,
Set2Set은 graph context, HX adapter는 유로 pairing, FeedHead는 희석되지 않은 공급 조건을
각각 담당한다.

## 7. Global graph embedding

5-layer GNN의 모든 local node hidden 384D를 Set2Set으로 모은다.

```text
All local nodes: [N_node, 384]
Set2Set processing steps: 3
Raw global graph embedding: 768D
Head global projection: 768 -> 384
```

Set2Set을 쓰는 이유는 단순 평균과 달리 graph 안의 중요한 node를 반복적으로 읽어
graph 전체 운전 상태를 만들기 위해서다. 384D로 투영한 뒤 graph의 모든 prediction
edge에 같은 global context를 전달한다.

encoder 내부에는 일반 task를 위한 다음 final node projection도 존재한다.

```text
[local node 384; raw global 768] = 1152
1152 -> 384 -> 384
```

그러나 현재 edge prediction head는 이 final node tensor가 아니라 **local GNN node
hidden 384D**를 source/destination 표현으로 사용한다.

## 8. HX inlet/outlet pair relation

열교환기에서는 동일한 HX node에 여러 inlet/outlet stream이 연결될 수 있다. 단순
source/destination 정보만으로는 어떤 inlet과 outlet이 같은 유로인지 모호하므로,
사전에 검증한 symmetric one-to-one pair metadata를 사용한다.

paired HX edge에 대해 다음 correction을 계산한다.

```text
Current edge embedding                384D
Paired edge embedding                 384D
HX side embedding                      16D
                                      ----
Pair relation input                   784D
784 -> 256 -> 384 = delta_e
```

relation MLP는 LayerNorm, GELU, dropout 0.1을 포함한다. 최종 갱신은 다음과 같다.

```text
e_pair = LayerNorm(e_current + sigmoid(gate_logit) * delta_e)
```

gate의 초기 유효값은 0.05다. 따라서 학습 시작 시 pair correction이 기존 edge 표현을
압도하지 않고 필요한 만큼만 커진다. pair가 없는 edge는 기존 embedding을 유지한다.
HX pair correction의 파라미터 수는 **300,977개**다.

HX pair feature는 FlowGNN 내부가 아니라 최종 edge descriptor를 만들기 직전에 적용한다.
따라서 R1 message-passing 구조를 유지하면서 HX 유로 대응 정보의 효과만 추가한다.

## 9. FeedHead64

### 9.1 직접 입력

graph sample의 train-fitted scaler로 정규화한 feed와 mask를 사용한다.

```text
[CH4, AIR, WATER] scaled values        3D
[CH4, AIR, WATER] validity masks       3D
                                       --
FeedHead input                         6D
6 -> 32 -> 64
= graph feed embedding                64D
```

Feed encoder는 LayerNorm과 GELU를 사용하며 dropout은 0이다. 파라미터 수는
**2,528개**다. 하나의 graph에서 만든 같은 64D vector를 그 graph의 모든 prediction
edge에 broadcast한다.

### 9.2 Node ratio feature와의 차이

- Node 경로: raw feed는 V_INPUT, log ratio는 V_INPUT과 BURNER에 들어가 GNN과
  Set2Set을 통과한다.
- FeedHead 경로: CH4/AIR/WATER 값과 mask 6D를 head 직전에 64D로 인코딩한다.
- FeedHead 자체에는 ratio 2개를 중복 concat하지 않는다.

두 경로를 함께 쓰는 이유는 node-level 반응 위치 정보와 graph-level 공급 조건을 모두
보존하기 위해서다. GNN이 feed 정보를 충분히 전달하면 node 경로를 활용할 수 있고,
전달 과정에서 희석되더라도 direct FeedHead 경로가 이를 보완한다.

## 10. 최종 edge descriptor

R1은 message passing은 relational 구조지만 최종 readout은 검증된 `legacy` descriptor를
사용한다. 여기서 legacy는 오래되어 불필요하다는 뜻이 아니라 R2/R3의 별도 양방향 edge
readout을 사용하지 않는다는 뜻이다.

```text
Source local node hidden              384D
Destination local node hidden         384D
Projected global graph hidden         384D
HX pair-aware edge hidden             384D
                                      ----
Base edge descriptor                 1536D

Direct FeedHead embedding              64D
                                      ----
Final property-head input            1600D
```

## 11. Hierarchical Reduced PI Head

### 11.1 Shared decoder

```text
1600 -> 768 -> 384
```

각 block은 Linear, LayerNorm, GELU, dropout 0.1을 사용한다. 768D와 384D가 다르므로
shared decoder 내부 residual은 사용하지 않는다.

### 11.2 Level-1 branches

```text
Condition branch
384 -> 96 -> 2
-> Temp, Pres

Fraction branch
384 -> 128 -> 7 logits
-> softmax(logits / 0.5)
-> H2O, H2, CH4, CO2, CO, O2, N2

Mass branch
384 -> 96 -> 1
-> Mass_Flow training-space value
```

fraction은 항상 0 이상이며 7개 합이 1이 된다. temperature 0.5는 일반 softmax보다
분포를 더 선명하게 만든다.

### 11.3 Level-2 Volume Flow

```text
Temp 1 + Pres 1 + fractions 7 + Mass_Flow 1 = Level-1 10D
detach(Level-1 10D)
10 -> 32 -> 1
-> Vol_Flow
```

Volume Flow는 1차 물성의 함수로 예측하되, Volume loss gradient가 condition,
fraction, mass branch를 역으로 흔들지 않도록 Level-1 입력을 detach한다. unfreeze
epoch은 없으므로 전체 학습 동안 detach가 유지된다.

### 11.4 최종 출력 순서

```text
0  Temp
1  Pres
2  Frac_H2O
3  Frac_H2
4  Frac_CH4
5  Frac_CO2
6  Frac_CO
7  Frac_O2
8  Frac_N2
9  Mass_Flow
10 Vol_Flow
```

최종 출력은 **11D**다. Mole_Flow는 예측하지 않는다. Density와 Enthalpy도 이 모델의
직접 출력이 아니며, 관련 rho/h/energy loss weight는 0이다.

## 12. Supervised loss

### 12.1 기본 property loss

Temp, Pres, Vol_Flow는 유효 mask가 있는 값에 대해 Smooth L1을 사용한다.

```text
SmoothL1(r) = 0.5*r^2 / beta,  |r| < beta
              |r| - 0.5*beta,  otherwise
```

### 12.2 Fraction log loss

fraction은 physical fraction에 다음 log 변환을 적용한 뒤 Smooth L1으로 비교한다.

```text
L_frac = 0.75 * mean_k SmoothL1(
    log(y_hat_k + 1e-6) - log(y_k + 1e-6)
)
```

log loss를 쓰는 동안 fraction 7개를 main loss에서 다시 계산하지 않으므로 중복
supervision이 없다. CLR loss와 별도 closure loss는 0이다. 실제 flow가 사실상 0인
edge는 `1e-8` 기준 zero-flow mask로 fraction loss와 fraction metric에서 제외한다.

### 12.3 Mass Flow log-space loss

physical Mass Flow `m`을 다음 training space로 변환한다.

```text
T_mass(m) = 2.0 * log(max(m, 0) + 1e-8)
```

Mass branch는 이 공간을 직접 예측하고 transformed target과 비교한다. Mass Flow의
log loss weight는 **2.0**이다. 매우 큰 유량이 작은 유량을 압도하지 않으면서도 Mass
Flow를 다른 성분보다 더 강하게 학습하기 위한 설정이다.

별도의 physical-space Mass Flow auxiliary loss는 비활성이다.

### 12.4 Target edge와 non-target edge update

Target edge 기본 weight는 5, 일반 edge weight는 1이다. 한 graph sample은 다음 순서로
학습한다.

```text
1. non-target edge 전체를 edge-group macro mean
   -> fresh forward -> backward -> optimizer step 1회

2. target edge 각각
   -> target edge별 fresh forward -> backward -> optimizer step 1회씩

3. 유효한 node PINN이 있으면
   -> supervised anchor와 함께 node update 1회
```

Target weight를 과거의 40이 아니라 5로 둔 이유는 target gradient를 강조하면서도 한
sample 안의 반복 optimizer step에서 gradient spike가 누적되는 위험을 줄이기 위해서다.

## 13. Node PINN

### 13.1 활성 loss

| PINN 항목 | 활성 | 내부 weight |
|---|---|---:|
| Node mass balance | 예 | 0.75 |
| Node component balance | 예 | 1.5e-7 |
| Node atom balance | 예 | 0.2 |
| Node energy balance | 아니오 | 0.0 |
| Density / Enthalpy / Volume auxiliary | 아니오 | 0.0 |

Node PINN 전체에는 `node_outer_weight=0.05`가 추가로 적용된다. node step의 supervised
anchor weight는 1.0이며 target weight 5는 anchor에 다시 적용하지 않는다.

### 13.2 Mass balance

node `n`의 예측 mass residual은 다음과 같다.

```text
r_mass(n) = sum(incoming Mass_Flow) - sum(outgoing Mass_Flow)
```

상대 residual의 분모는 true incoming/outgoing 절대 유량 합이다.

```text
s_mass(n) = max(
    sum(|true incoming flow|) + sum(|true outgoing flow|),
    1.0
) + 1e-6

r_mass_rel(n) = r_mass(n) / stop_gradient(s_mass(n))
```

### 13.3 Component balance

species `k`에 대해 component mass flow를 `Mass_Flow * fraction_k`로 만든다.

```text
r_component(n,k)
  = sum_in(m_dot * x_k) - sum_out(m_dot * x_k)
```

분모는 true component flow의 incoming/outgoing 절대값 합이며 같은 방식으로 최소 1.0과
epsilon 1e-6을 적용한다.

### 13.4 Atom balance

fraction, Mass Flow, molecular weight와 원소 조성으로 원자별 몰 유량을 계산한 뒤
node 입출력 차이를 구한다.

```text
r_atom(n,a)
  = sum_in(atom_molar_flow_a) - sum_out(atom_molar_flow_a)
```

### 13.5 안전한 residual loss

세 residual 모두 relative normalization 후 `[-10, 10]`으로 clamp하고 delta 0.5의
Huber loss를 사용한다. NaN/Inf, invalid edge, 적용할 수 없는 node는 mask로 제외한다.

### 13.6 PINN schedule

초기 supervised prediction이 형성되기 전에 물리 loss가 모델을 끌고 가지 않도록 node
PINN만 단계적으로 켠다.

| Epoch | Node PINN multiplier |
|---|---:|
| 1-5 | 0.0 |
| 6-7 | 0.5 |
| 8 이후 | 1.0 |

따라서 epoch 1부터 diagnostic raw PINN 값이 로그에 보일 수 있어도 실제 weighted
backprop 기여는 multiplier가 0이면 0이다.

## 14. Epoch sampler

학습 pool 전체를 매 epoch 모두 쓰지 않고 2,000개의 고유 graph sample을 선택한다.

```text
Base sampling  1,000
Hard sampling  1,000
--------------------
Epoch total    2,000
```

### 14.1 Base 1,000

기본 후보는 공정 균형과 중복 방지를 유지하며 다음 mixture를 사용한다.

| Bucket | 명목 비율 |
|---|---:|
| Uniform | 25.0% |
| Sparse-positive fraction | 37.5% |
| Property quantile balance | 25.0% |
| Mass-flow tail slot | 12.5% |

현재 별도 mass-flow-tail builder는 비활성이라 유효 후보가 부족한 bucket은 sampler의
fallback으로 채운다. 한 epoch 안에서 같은 sample을 중복 선택하지 않는다.

### 14.2 Hard 1,000

| 목적 | 개수 | 핵심 범위 |
|---|---:|---|
| Target Frac_CO | 400 | P03_E014 중심 + 지원 target edge |
| Target Mass_Flow | 400 | 고유량 240 + 극고유량 160 |
| Target Frac_CH4 | 200 | P07/P06/P08 target edge |

Mass Flow hard sample은 다음처럼 나눈다.

```text
High flow:    100,000 <= Mass_Flow < 500,000  -> 240
Extreme flow: Mass_Flow >= 500,000            -> 160
```

Base와 hard candidate가 겹치지 않게 선택하며, 부족한 hard candidate는 random fallback으로
채운다. hard sampling은 약한 영역을 보강하되 전체 자연 분포를 절반 유지하기 위한
구성이다.

## 15. Validation과 checkpoint 선택

- 매 epoch validation 수행
- 전체 validation pool에서 seed 기반 random 1,000개 선택
- epoch마다 다시 sampling
- monitor: `val_target_mean_r2`
- monitor mode: max
- early stopping patience: 5
- best checkpoint만 별도 보존

개별 성분 R2와 all-edge R2는 모델 해석에 사용하고, checkpoint 선택은 target edge의
aggregate validation R2를 사용한다. Test split은 학습 및 best epoch 선택에 사용하지
않는다.
