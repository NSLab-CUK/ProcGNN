# Model 260716

This document is the canonical description of the current Model 260716 training
recipe. It reflects the latest full-data, sample-hybrid target-edge update path
and the stabilized node-level PINN loss.

Older 10% unseen-transfer notes and legacy `edge_step_pi` recipes are not the
current final model basis.

Fold 1 reference sizes:

| Split | Approx rows |

Per epoch, training samples only 2% of the train pool:

```yaml
train.epoch_sampler.enabled: true
train.epoch_sampler.epoch_fraction: 0.02
train.batch_size: 1
```

The epoch sampler is process-balanced and target-focused. It does not expand the
dataset; it changes which rows are drawn from the train pool each epoch.

Current default mode:

```yaml
train.epoch_sampler.mode: scheduled_predefined_hard
```

The previous 5-bucket sampler (`uniform`, `sparse_positive`,
`quantile_balance`, `mass_flow_tail`, `hard_target_edges`) is not used by this
model_260716 default path. The current path first assigns a balanced quota per
process, then splits each process quota into random and predefined-hard samples.

| Displayed epoch | Random quota | Hard quota |
|---:|---:|---:|
| 1-5 | 100% | 0% |
| 6-7 | 80% | 20% |
| 8+ | 70% | 30% |

Hard-target-edge rules focus on target-edge properties that were weak in recent
target-feature metrics:

| Rule | Property | Target edge IDs |
|---|---|---|
| `low_target_frac_ch4` | `Frac_CH4` | `P07_E017`, `P06_E023`, `P08_E016`, `P07_E016`, `P04_E020` |
| `low_target_frac_co` | `Frac_CO` | `P07_E017`, `P06_E023`, `P08_E016`, `P07_E016`, `P04_E020` |
| `low_target_frac_co2` | `Frac_CO2` | `P07_E017`, `P08_E016`, `P06_E023`, `P07_E016`, `P04_E020` |

Hard-target sampling uses positive target-stream values:

```yaml
min_value: 1.0e-08
max_value: 1.0
```

The sampler remains process-balanced first. For fold 1, the 2% epoch size is
about 1441 rows, so each process receives roughly equal quota before that
process quota is split by the epoch schedule above. If a process has fewer
available predefined-hard samples than its hard quota, the missing hard quota is
filled from that same process random pool. Random sampling does not explicitly
remove hard samples, so natural hard-sample overlap can still occur.

Legacy adaptive dataset expansion is off for this final recipe:

```yaml
train.target_edge_augmentation.enabled: false
train.rare_positive_sampler.enabled: false
train.rare_target_edge_augmentation.enabled: false
```

## Model Architecture

The model is the edge-all PI grouped-property GNN path:

```yaml
model.edge_head_type: pi_grouped_property
model.use_edge_decoder: true
model.use_edge_stream_head: false
model.fraction_activation: softmax
model.fraction_temperature: 0.5
```

Core head settings:

| Setting | Value |
|---|---:|
| Edge decoder hidden dim | 128 |
| Edge operation dim | 3 |
| Edge structural dim | 3 |
| Property head hidden dim | 128 |
| Property head layers | 2 |
| Dropout | 0.1 |
| Condition head output dim | 2 |
| Fraction head output dim | 7 |
| Flow head output dim | 3 |

The grouped edge head predicts 12 direct supervised stream properties:

```text
Temp
Pres
Vol_Flow
Mole_Flow
Mass_Flow
Frac_H2O
Frac_H2
Frac_CH4
Frac_CO2
Frac_CO
Frac_O2
Frac_N2
```

It also emits separate physical auxiliary heads:

```text
rho_pred -> Density
h_pred   -> Enthalpy
```

Species order:

```text
H2O, H2, CH4, CO2, CO, O2, N2
```

### Target Branch Hidden Adapter

The baseline `model_260716_full100k_outer5_epoch2pct_val1000_targetfocus_samplehybrid.yaml`
keeps the adapter disabled.  The adapter experiment is isolated in:

```text
configs/experiment/pinn/model_260716_full100k_outer5_epoch2pct_val1000_targetfocus_samplehybrid_targethiddenadapter.yaml
```

This adapter does not modify the raw 2051D edge feature
`[src node emb, dst node emb, global emb, edge_struct_attr]`.  It is applied
inside `PIGroupedPropertyHead`, immediately before each existing branch output
layer:

```text
condition: 2051 -> 128 hidden -> target adapter -> existing Linear(128, 2)
fraction:  2051 -> 128 hidden -> target adapter -> existing Linear(128, 7) -> softmax(temp=0.5)
flow:      2051 -> 128 hidden -> target adapter -> existing Linear(128, 3)
```

Each branch adapter is:

```text
LayerNorm(128) -> Linear(128, 16) -> GELU -> Linear(16, 128)
```

with the final up-projection zero-initialized.  The residual is target-edge only:

```text
h'_k = h_k + m_target * alpha * A_k(detach(h_k))
```

where `alpha=0.1` in the adapter YAML.  The original hidden identity path is not
detached.  Existing branch module names and state-dict keys remain unchanged;
only new adapter keys are added.  Density and Enthalpy do not have separate
adapters; they receive the adapted `Temp`, `Pres`, and fraction predictions via
the existing thermo input path.

## Training Update Flow

The current backward mode is:

```yaml
train.backward_mode: sample_hybrid_target_edge_step_pi
```

For each graph sample:

1. Compute one non-target edge loss over all non-target edges.
2. Backprop and optimizer step once for the non-target mean.
3. For each target edge, run a fresh forward pass.
4. Backprop and optimizer step once per target edge.
5. Run one node-level PINN update when node PINN is enabled.

Typical compact log:

```text
updates=opt5/t3/n1/node1 groups=t3/nt27 fwd=5
```

Meaning:

| Field | Meaning |
|---|---|
| `opt5` | 5 optimizer steps for this sample |
| `t3` | 3 target-edge optimizer steps |
| `n1` | 1 non-target optimizer step |
| `node1` | 1 node PINN optimizer step |
| `groups=t3/nt27` | 3 target groups and 27 non-target groups |
| `fwd=5` | 5 fresh forward passes |

The target-edge supervised weight remains:

```yaml
train.edge_weight_target_edge: 40.0
train.edge_weight_default: 1.0
```

## Supervised Loss

The main edge supervised loss is SmoothL1:

```yaml
train.pi_main_loss_type: smooth_l1
train.lambda_main: 1.0
```

R2-style losses are disabled as training losses:

```yaml
train.use_all_edge_r2_loss_in_edge_step_pi: false
train.use_primary_frac_loss_in_edge_step_pi: false
```

R2 values are metrics for validation, diagnosis, and checkpoint selection. They
are not backprop losses.

## Fraction And Mass Supervision

Fractions use softmax predictions and log-space supervision:

```yaml
model.fraction_activation: softmax
model.fraction_temperature: 0.5
train.pi_fraction_loss_type: log
train.pi_fraction_log_eps: 1.0e-6
train.pi_fraction_log_loss_weight: 0.75
```

Conceptually:

```text
L_frac = SmoothL1(log(clamp(frac_pred, eps)), log(clamp(frac_true, eps)))
```

Mass_Flow uses scaled-log supervision:

```yaml
train.pi_mass_flow_output_space: log1p
train.mass_flow_transform: scaled_log
train.mass_flow_log_scale: 2.0
train.mass_flow_log_eps: 1.0e-8
```

Conceptually:

```text
y_mass = 2.0 * log(Mass_Flow + eps)
Mass_Flow = exp(y_mass / 2.0) - eps
```

## PINN Loss Structure

The final node-level PINN uses four node losses plus two property-consistency
head losses:

| Term | Meaning |
|---|---|
| node mass | node-level mass conservation |
| node component | nonreactive node component-flow conservation |
| node atom | reactive node atom conservation |
| node energy | node-level enthalpy-flow + Q/W conservation |
| rho | Density consistency auxiliary loss |
| h | Enthalpy consistency auxiliary loss |

Volume duplicate loss is off:

```yaml
train.use_volume_loss: false
train.lambda_volume: 0.0
train.use_enthalpy_flow_loss: false
train.lambda_enthalpy_flow: 0.0
```

### Node Mass

For node `v`:

```text
r_mass(v) = (sum_in Mass_pred - sum_out Mass_pred)
            / stopgrad(max(sum_in |Mass_true| + sum_out |Mass_true|, scale_floor) + eps)

L_mass = mean(Huber(r_mass(v), 0))
```

Current stabilization:

```yaml
loss_type: huber
huber_delta: 1.0e-3
scale_floor: 1.0e-4
prediction_filter.max_abs_residual: variant-specific
```

The prediction filter excludes only the node PINN term when
`abs(r_mass)` is too large. Edge supervised learning for that sample still
continues.

### Node Component

For species `s` on nonreactive nodes:

```text
component_flow_s = Mass_Flow / mixture_MW * Frac_s

r_comp(v, s) = (sum_in component_pred_s - sum_out component_pred_s)
               / stopgrad(max(sum_in |component_true_s| + sum_out |component_true_s|, scale_floor) + eps)

L_component = mean(Huber(r_comp(v, s), 0))
```

Current stabilization:

```yaml
component_flow_threshold: 1.0e-8
scale_floor: 1.0e-4
loss_type: huber
huber_delta: 1.0e-3
```

### Node Atom

For atom `a` on reactive nodes:

```text
atom_flow_a = sum_s component_flow_s * atom_count(s, a)

r_atom(v, a) = (sum_in atom_pred_a - sum_out atom_pred_a)
               / stopgrad(max(sum_in |atom_true_a| + sum_out |atom_true_a|, scale_floor) + eps)

L_atom = mean(Huber(r_atom(v, a), 0))
```

Current stabilization:

```yaml
atom_flow_threshold: 1.0e-8
scale_floor: 1.0e-4
loss_type: huber
huber_delta: 1.0e-3
```

### Node Energy

For node `v`:

```text
Hdot = Mass_Flow * Enthalpy

r_energy_pred(v) =
    (sum_in Hdot_pred + Q + W - sum_out Hdot_pred)
    / stopgrad(max(sum_in |Hdot_true| + sum_out |Hdot_true| + |Q| + |W|, scale_floor) + eps)

L_energy = mean(Huber(r_energy_pred(v), 0))
```

The energy term has two guards.

First, a true-data consistency filter:

```text
r_energy_true(v) =
    (sum_in Hdot_true + Q + W - sum_out Hdot_true)
    / stopgrad(max(sum_in |Hdot_true| + sum_out |Hdot_true| + |Q| + |W|, scale_floor) + eps)

use node only when abs(r_energy_true) <= 0.01
```

Second, a prediction residual guard:

```text
use node only when abs(r_energy_pred) <= variant-specific max_abs_residual
```

This prevents early-training Hdot explosions from dominating gradients while
keeping the supervised edge loss unchanged.

Current energy settings:

```yaml
loss_type: huber
huber_delta: 1.0e-3
scale_floor: 1.0e-3
use_process_main_qw: true
signed_work_input: true
hx_total_balance_only: true
use_q_hx: false
consistency_filter.max_true_normalized_residual: 1.0e-2
```

## Runtime Health Checks

In compact logs:

```text
edge=t.../nt...
pinn=(mass/component/atom/energy/volume)
updates=opt.../t.../n.../node...
gnorm=...
```

Watch for:

| Signal | Interpretation |
|---|---|
| `gnorm=inf` | still unstable; stop and use a safer variant |
| repeated `gnorm > 1e9` | node PINN guard may still be too loose |
| `node_energy_pred_residual_rejected_count > 0` | energy prediction guard is active |
| `node_mass_pred_residual_rejected_count > 0` | mass prediction guard is active |
| target/all-edge property R2 improving | run is useful |

Do not judge final quality from mean-only metrics. Use target and all-edge
property-level metrics, especially fraction properties, Mass_Flow, Density, and
Enthalpy.
